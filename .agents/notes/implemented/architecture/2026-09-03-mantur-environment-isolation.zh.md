# Agent Note: 隔离漫途在线环境

Status: implemented

[English](2026-09-03-mantur-environment-isolation.md) | 中文

## 问题

漫途登录与广场功能共享一个已配置 Hub origin 和一个凭据 key。把开发版指向测试部署时，所有调用方的 origin 都会被替换，但系统没有表示当前环境、保留两个端点，也无法阻止端点变更后继续使用已保存授权。浏览器目录状态还可能比实时配置变更存活更久。

登录、Skill 广场和配方广场都依赖同一账号服务。分别配置会允许账号授权指向一个部署，而目录或下载指向另一个部署。

## 决策

`dsh-authorization-manturhub` 持有一个线上部署和一个可选测试部署。`environment` 选择 `production` 或 `test`；`baseUrl` 命名线上环境，默认为 `https://hub.mantur.ai`；选择测试环境前必须提供 `testBaseUrl`。两个端点都必须是不含凭据、路径、查询或片段的 HTTP(S) origin，并且必须彼此不同。

提供方为每个已配置 origin 注册一个授权 flow。公共线上 origin 保留原凭据 key，因此现有线上登录可以延续。其他每个授权 key 都包含环境名和完整 origin 的 SHA-256 指纹。线上与测试环境因此无法读取对方的授权，替换测试 URL 也不会把原测试授权暴露给新服务器。

`manturhub` 设置命名空间只持久化环境选择与端点。账号 Remote 公开浏览器安全的当前端点，并通过该命名空间提交环境变更。切换成功后刷新浏览器。登录、目录、详情、配方与下载请求已经全部通过 `manturAccount.request()` 进入 ManturHub，因此它们读取同一当前部署，且刷新会丢弃上一部署的内存 UI 状态。

已安装 Skill 仍属于本机产品资产。本机实时 Skill 目录与安装器记录在环境之间共享；更换在线环境不会删除或隐藏已安装 Skill。

## 考虑过的替代方案

**保留一个可编辑 base URL 和一个授权。** 这样切换很短，但变更后的 URL 可能继承为另一台服务器签发的授权，而且设置与界面都无法区分线上与测试。

**分别为每个广场和登录提供端点选择器。** 这会产生多个开关，并允许部署不匹配。由账号持有一个选择器，可使所有漫途在线请求保持一致。

**分别发布线上与测试应用。** 分开的应用数据目录可以提供更强的全产品隔离，但会为日常开发操作复制打包与发布流程。origin-scoped 授权与浏览器刷新可在同一安装中隔离在线状态。

**按环境分割已安装 Skill。** 这会防止测试安装影响线上可见的本地目录，但也会仅因远程目录变更就让本地能力消失。本次要求的隔离适用于在线内容与凭据；已安装文件保留原有本地所有权与冲突检查。

## 后果

“漫途账号”设置页提供快速线上/测试选择器，并要求显式填写测试 URL。切换会取消活跃登录尝试、持久化选择，然后刷新客户端。返回某个环境时，只会恢复属于该 origin 的原登录。

当前所有 ManturHub 目录、配方、详情与下载调用都会跟随已选 origin，无需消费方单独配置。设置文件不包含账号密钥。公共线上服务的现有用户会保留当前本机登录。

开发者选择测试环境前必须提供与线上不同的测试 origin。已安装 Skill 与其安装器状态仍为共享本场数据，因此常规版本与本地冲突规则仍跨环境生效。

## 测试

回环 Hub 集成测试会分别登录线上与测试环境、验证独立存储记录、证明公开请求跟随当前 origin、切回线上授权，并确认更换测试 origin 后从未登录状态开始。它们还会拒绝缺失、无效或与线上相同的测试端点，并确认设置文档包含 URL 但不含 API Key。浏览器 store 与组件测试覆盖校验、Remote 写入、刷新、失败呈现与设置控件。
